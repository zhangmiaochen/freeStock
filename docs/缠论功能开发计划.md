## 0. 现状与结论

| 项 | 结论 |
|---|---|
| 技术栈 | Go 1.26 + Wails3（alpha.74）+ Vue3 + ECharts |
| 后端入口 | `internal/service/StockService` 一个服务统一下发给前端 |
| 行情来源 | `Provider` 接口（free-stockdb HTTP / cnequity 数据湖），`KlineHistory` 供单只全历史 |
| 选股 | `internal/service/screener.go`：快照→板块→数据湖→技术，**技术层已是最后一层** |
| K 线页 | `frontend/src/views/KlineView.vue` + `components/kline/KlineChart.vue`（ECharts，多面板） |
| 周期聚合 | 前端 `lib/indicators.ts` 的 `aggregate()`（ISO 周 / 自然月 / 自然年），后端需**同口径**复刻 |
| 绑定 | `wails3 generate bindings -ts` 生成 `frontend/bindings/**`，前端只通过 `lib/backend.ts` 调用 |

**核心结论**：缠论必须做成**独立引擎包**（`internal/chanlun`），个股图与选股只消费它的输出；
不能碰 `KlineChart.vue` 之外的页面逻辑，也不能把缠论条件写成选股条件的一部分。

## 2. 各模块设计要点

### 2.1 级别（Level）

| 值 | 含义 | 权重（默认） |
|---|---|---|
| `year` | 年线 | 1.0 |
| `month` | 月线 | 0.9 |
| `week` | 周线 | 0.8 |
| `day` | 日线 | 0.6 |
| `day-stroke` | 日线笔（仅日 K 时的最小级别） | 0.4 |

- **级别独立**：每个级别用**自己的 K 线序列**独立算分型→笔→线段→中枢→走势→信号。
- 大级别**只**用于：定方向、定操作级别、判断小级别信号是否值得参考；**禁止**用它生成小级别画线。
- 只有日 K 时：最小级别 = 日线笔，操作级别 = 日线，必须常驻提示「无法做真正分钟级区间套，精度有限」。

### 2.2 包含处理 → 分型 → 笔 → 线段

| 步骤 | 规则 | 可追溯信息 |
|---|---|---|
| 包含 | 方向由前一根合并 K 线决定；向上取高高、低高；向下取高低、低低 | 每根合并 K 线记录**原始下标区间**与极值所在原始下标 |
| 分型 | 合并序列上的三根结构：顶 = 中间最高且高于两侧；底 = 中间最低且低于两侧 | 形成时间 = 极值日；确认时间 = 第三根日 |
| 笔 | 顶底交替；两个分型的合并下标差 ≥ 4（即至少 5 根合并 K 线）；顶价 > 底价 | 起止原始下标/日期/价格；确认时间 |
| 笔延伸 | 同类型新分型更极端则替换终点（不中断笔） | 延伸记录 |
| 线段 | 由笔构成；**反向笔跌破前一个回抽低点（向上线段）+ 后续向上笔未创新高** → 确认结束 | 起止、破坏确认时间、状态 |
| 线段延伸 | 未确认破坏前沿原方向延伸 | — |

> 线段的严格定义依赖特征序列分型。本实现采用等价的「**笔破坏 + 反向不创新高/新低**」判定，
> 保证：线段与笔方向交替、端点不重叠、满足结合律；代码注释里写明这一取舍。

### 2.3 中枢 / 走势类型

- **中枢**：连续 3 笔的价格区间重叠；`ZG = min(三笔最高)`, `ZD = max(三笔最低)`，`ZG > ZD` 才成立。
- 状态：形成（第 3 笔确认）、延伸（后续笔仍与 [ZD,ZG] 相交）、扩展（笔数 ≥ 9 且仍重叠，标记）、新生（离开后重新成立）。
- **级别**：中枢继承其构成走势的级别（本实现 = 当前分析级别）。
- **走势类型**：连续 2 个及以上**同向不重叠**的中枢 → 上涨/下跌趋势；中枢重叠或仅 1 个 → 盘整；
  **无中枢 → 走势未完成**，不输出趋势背驰、不输出三类买卖点。
- 「反转」不是独立走势类型，只用信号状态（反转候选/反转确认）表达。

### 2.4 背驰

- 前提：趋势背驰必须先有趋势（≥2 同向中枢）；盘整背驰只用于单中枢；**无中枢不背驰**。
- 比较对象：**离开中枢的同向两段**（趋势：最后一个中枢的离开段 vs 进入该中枢的那一段；盘整：中枢前后的同向段），不是相邻两笔、也不是简单比 MACD 柱。
- 力度 = 四维加权（权重可配）：
  - 结构：是否创新高/新低、是否被前段包含、段内笔数；
  - MACD：该段 MACD 柱面积、DIF/DEA 峰值；
  - 斜率：单位时间价格变化 + K 线实体；
  - 量能：均量对比（**仅辅助**，可关）。
- 输出率 `ratio = strengthB / strengthA`，`ratio < 1 - 阈值` 判背驰；并输出每一维的分值，供界面展示依据。
- 常驻提示：背驰只保证回到最后一个中枢，不保证反转；后续三种可能（反转 / 盘整 / 背驰失败）。

### 2.5 买卖点与状态机

| 类型 | 定义 | 状态迁移 |
|---|---|---|
| 一买/一卖 | 趋势背驰 + 分型确认 | 候选（背驰成立、分型未确认）→ 触发（分型确认）→ **确认（二买/二卖确认，或反向笔破坏原趋势最后一个中枢且回抽不回）** → 失效（跌破背驰低点/涨过背驰高点）→ 过期（N 根内未确认） |
| 二买/二卖 | 一买/一卖后，次级别回抽不破前低/不破前高 | 候选（回抽中）→ 触发（回抽分型确认）→ 确认（反向突破回抽起点）→ 失效/过期 |
| 三买/三卖 | 突破中枢后回抽不回中枢（三买：回抽低点 > ZG；三卖：反抽高点 < ZD） | 可独立出现；同上状态机 |

> **单笔突破前高/前低不构成一买/一卖确认。** 背驰只代表力度衰竭、不保证反转，
> 所以一买/一卖被定性为"候选/触发"，确认必须来自二买/二卖或原趋势最后一个中枢
> 被反向破坏（三买/三卖结构）。这也决定了状态映射：背驰失败时不能显示"反转候选"。

- 每个信号必须带：级别、类型、方向、状态、形成/触发/确认/失效时间、依据、综合分、冲突标记。
- **先判状态再出信号**：状态（数据不足 / 盘整 / 上涨趋势 / 下跌趋势 / 反转候选 / 反转确认 / 失效）与信号映射严格按方案 §7.3 的表。
- 信号按「级别 → 状态 → 类型 → 方向 → 时间」排序（方案 §8.1）。

### 2.6 综合分与冲突

```
factors = 级别权重 × 类型权重 × 确认强度 × 背驰强度 × 位置权重 × 环境权重
综合分 = 100 × (factors)^(1/6)      // 几何平均：保留乘性排序，同时稳定落在 0~100
```
- 六个因子都落在 [0,1]，界面展示分项（`ScoreBreakdown`），不展示一个无法解释的黑盒数字。
- 冲突：大级别压制小级别；**当前仍有效**的同级别反向信号，且锚定同一/相邻中枢（背驰信号看同一背驰）→ `Conflict=true` + 文案「结构矛盾」，且**不输出高优先级**（排序下沉、综合分乘 0.5）。已失效/过期的历史信号不参与，避免"去年的一买和今年的三卖"被误判。
- 多级别共振（同方向同级别区间套）→ 综合分乘 1.15（封顶 100）。

### 2.7 无未来数据与回放

- 所有结构在**确认时**才进入结构序列：分型等第三根、笔等分型确认、线段等反向破坏、中枢等第三笔、背驰等离开段走完。
- 每个信号记录形成/确认时间，**不允许用后续走势修改历史信号**。
- `replay.go`：对每个前缀 i 重新分析，输出该时点的状态快照；`Audit(bars, cfg)` 逐条校验历史信号的触发时间在「当时」确实已成立（回归测试用）。
- 回放支持：暂停 / 快进 / 跳到指定日；**步长与最大步数可配置**（默认 1 根，最多 2000 步）。

### 2.8 可视化标注（前后端契约）

后端输出**按日期**（`YYYYMMDD`）而不是下标 —— 前端周期聚合口径与后端一致，但用日期映射更抗错位：

```jsonc
{
  "bars": [{"date": 20260930, "mergedStart": 12, "mergedEnd": 15}],  // 包含处理可追溯
  "fractals": [{"date": 20260912, "type": "top", "price": 12.34, "confirmDate": 20260913}],
  "strokes":  [{"startDate":…, "endDate":…, "startPrice":…, "endPrice":…, "confirmed":true}],
  "segments": [{"startDate":…, "endDate":…, "startPrice":…, "endPrice":…, "confirmed":true}],
  "pivots":   [{"startDate":…, "endDate":…, "zg":…, "zd":…, "level":"day", "status":"extension"}],
  "divergences": [{"date":…, "kind":"trend", "direction":"down", "ratio":0.72, "dims":{…}}],
  "signals":  [{"date":…, "type":"buy1", "state":"confirmed", "level":"day", "score":78.4,
                "formDate":…, "triggerDate":…, "confirmDate":…, "reasons":[…]}],
  "notes":    ["…"],
  "disclaimer": "仅作参考，不构成投资建议"

```

前端 `lib/chanlun.ts` 负责：日期 → 下标、笔/线段折线数组、中枢 markArea、分型/买卖点散点与标签。
**图只消费标注，不重算缠论。**

### 2.9 选股扩展（最后一层）

```go
type ChanlunScreenCondition struct {
    Enable          bool     `json:"enable"`          // 总开关：关闭时完全不调用缠论

    RequireDivergence bool   `json:"requireDivergence"`

    ConfirmedOnly   bool     `json:"confirmedOnly"`

    MultiResonance  bool     `json:"multiResonance"`

```

- 关闭：`ScreenStocks` 里**一个分支都不进**，原流程与结果完全不变（有回归测试）。
- 启用：只在技术层完成之后执行，作用于 `passed`；不改变任何已有条件的语义。
- 输出：`ScreenItem.chanlun`（命中原因、状态、级别与位置、走势类型、中枢/背驰摘要、买卖点列表、
  综合分、冲突说明、适配性评分、风险提示）；结果按综合分降序（同分再按代码）。

## 5. 风险与已知限制（会在界面与 README 里写明）

1. **只有日 K 数据时**：最小级别是日线笔，区间套只能在日线内部做，**精度有限**；不是 bug。
2. **线段判定**采用「笔破坏 + 反向不创新高/新低」的等价化简，与教科书特征序列分型在少数边界形态上可能给出不同分段；代码注释与界面提示都会说明。
3. **多义性**：本实现选「有利于当下操作」的一种分解；出现无法消解的分歧时标记「结构矛盾」并降权，不硬给高优先级。
4. **性能**：单只票单级别分析是毫秒级；选股对候选集逐只分析，候选多时耗时线性增长（有进度事件）。
5. **不预测**：所有输出都是状态/候选/确认/失效，没有任何「必涨必跌」结论；常驻免责声明。

### 6.2 实现期发现并修掉的问题（都写了注释）

1. **相邻中枢共用端点**：`[prev.EndIndex, next.StartIndex]` 恒为空 → 趋势背驰永远检测不出来。
   改成两段都取"离开各自中枢的同向一笔"，长度可比。
2. **MACD 面积随段长膨胀**：单笔 vs 整段比较时面积差几十倍，力度比恒 > 1。
   改成按单位 K 线折算。
3. **背驰阈值没有生效**：`compareLegs` 只算比值、调用方没和阈值比，导致把"力度更强"也当背驰。
4. **过期判定被晚到的确认绕过**：触发后 3 个月才出现的确认会把信号标成"确认"。
   现在终止事件（失效/过期）先发生则**不再记录**确认时间，状态为过期/失效。
5. **三买/三卖未关联背驰时 `DivergenceIndex` 是零值**：被误认为关联第 0 个背驰，综合分取错。
   显式置 -1。
6. **信号无限增长**：十年日线会攒出上百条失效信号。现在候选/触发全留，确认/失效/过期每种按时间留最近 3 条，并做类型+形成+触发去重。
7. **ECharts 少注册 `ScatterChart` → 整个图表永久冻结**（用户反馈「窗口放大缩小，K 线图不跟着变」）：
   分型/买卖点用的是散点，但 `echarts.use([...])` 里没注册 `ScatterChart`。ECharts 会接受第一次
   option，随后在 `performSeriesTasks` 里读 `seriesModel.dataTask` 抛错，并把内部
   「正在更新」标志留在 `true` —— 之后所有 `setOption` / `resize` 直接 return，画布停在上一次尺寸。
   修法：注册表抽成一份 `frontend/src/lib/echarts.ts`；ResizeObserver 里**自检**尺寸，
   不符就重建实例；`render()` 抛错也重建；新增 `tests/echartsRegistration.spec.ts`
   （去掉 `ScatterChart` 会失败，已实测）。详见 README §12.6。
8. **复权被折算两次，前复权显示成后复权价**（用户反馈「安泰科技显示 104 块多，实际 14 块」）：
   数据湖的 `KlineHistory` 已按全局口径（默认 hfq）复权，`GetKline` 又用另一套因子折算一次。
   000969 原始 14.81 → 显示 104.99，600519 原始 1329 → 显示 11804。
   修法：`KlineHistory` 只返回原始价；新增 `Provider.AdjustQuotes` 按用户选择（none/qfq/hfq）
   在**出口只折算一次**（数据湖用 `meta/adj_factors_cache`，stockdb 用复权表）；
   K 线页与缠论 `loadChanlunBars` 共用同一个出口，保证标注与蜡烛同尺度。
   回归测试 `TestAdjustQuotesQfqAnchorsLatest`（前复权最新一根必须等于原始价）。
9. **「结构矛盾」误报太多**（用户问「有时候提示结构矛盾是什么意思」）：
   原来只要同级别反向信号的有效区间重叠就标矛盾，而已确认信号一直有效到被价格破坏，
   于是 2021 年的一买会和 2026 年新中枢的三卖互判矛盾（000969 11 条信号里 10 条被标）。
   现在只对**当前仍有效**（非失效/过期）且锚定**同一/相邻中枢**（或同一背驰）的反向信号判冲突；
   回归测试 `TestConflictOnlyForSameStructure`（相隔 3 个中枢不判、相邻判、同一背驰判、历史信号不判）。
10. **选股与 K 线页结论不一致**（用户问「K 线页显示结构矛盾，为什么选股还把它选出来」）：
    根因是两处窗口不同 —— K 线页全历史（002925 为 1400 根 / 15 个中枢），选股默认窗口
    `500×2+60` 个自然日（约 700 根 / 7 个中枢），命中的是不同年份的三买。
    修法：选股结果新增 `bestDate`（命中信号日期）并在表格显示；命中原因与结果 notes
    写明「缠论分析窗口：开始日 ~ 截止日」及"K 线页为全历史，结构可能不同"；
    K 线面板底部也常驻这条口径说明；条件面板的字段名从「日均窗口」改为「分析窗口」。
    另外，用户会拿 K 线提示里的日期（信号**形成/触发**的那根 K）和选股里的日期对比：
    现在表格日期带「确认/触发/形成」前缀，K 线提示里同时列出形成/触发/确认三段，
    例如 301366 的 08-13（形成）与 09-28（确认）是同一条三买。

### 6.6 补充落地：「走势终完美」与「背驰 ≠ 反转」

这一轮针对两条最容易说过头的理论做了结构性补强（详见 README §12.7）。

| 理论要求 | 之前 | 现在 |
|---|---|---|
| 走势终要完成、完成必然转化 | 只有静态类型（盘整/上涨/下跌） | `Trend.status`（形成中/延伸中/已完成）+ `completedDate` / `completionReason` / `completedBy`；完成判据用**已确认的笔**破坏最后中枢 |
| 完全分类、不预测只应对 | 只有一句 note | `Trend.outlook`：三种后续可能 + 条件 + 状态（进行中/暂停/待发生/已确认/已排除） |
| 背驰后三种可能 | 只有 note 文案 | `Divergence.outcomes`：反转 / 盘整 / 背驰失败，各带状态、条件、日期；取最早发生者为 `outcome` |
| 一买只是候选，确认靠二买或破坏原中枢 | 单笔突破前高就标"确认" | 单笔突破不再确认；确认 = 二买/二卖确认（回填）或反向笔破坏最后中枢且回抽不回 |
| 背驰失败时不能当买点 | 仍显示"反转候选买" | 状态改为"下跌趋势（底背驰失败）"，并写明背驰不构成买点 |

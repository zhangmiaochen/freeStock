# 趋势低吸（`trend_pullback_low_buy`）策略规则

本文档总结 freeStock「组合管理」中**趋势低吸**策略的**买入 / 卖出 / 仓位**规则。

所有常量与判定都逐条对照过代码（Go 实现，`internal/score/`、`internal/backtest/`），
并与原 Python 项目 `D:\workspace\python\stock\tushare-stock-tonyz\pythonProject\pythonProject`
的对应函数核对过等价性。

> 数据源不同导致的部分差异不影响本文档描述的**规则本身**；规则是逐字对齐的。

---

## 一、总体结构

趋势低吸是**广度驱动**的策略，与其它策略最大的不同是：

**「今天能持几只股票、每只买多少」不是配置定的，而是由当天的「低吸广度就绪数」决定的。**

```
低吸广度就绪数（ready）
   ├── 决定「动态目标只数」(desired target)
   ├── 决定「建仓层数」(每只占总资产的几份)
   ├── 决定「能不能开新仓」（>=1000）
   ├── 决定「要不要强制清仓」（<900）
   ├── 决定「候选的 dd20 区间」（>=1200 用紧档）
   └── 决定「是不是弱周期假热度」（>=2400 且长周期未就绪 → 关闸）
```

### 低吸广度就绪数（ready）的定义

**在「范围过滤之前」的全市场行情帧上统计**，与该策略、与该组合范围无关：

```
ready = 当日满足以下条件的股票只数：
    close > 0
    且 ma60 > 0
    且 close > ma60
    且 ma20 > ma60
```

**样本集必须套 A 股代码前缀白名单**（原实现 `_load_market_frame`）：

```
600 601 603 605 688 689 000 001 002 003 300 301
```

即**不含北交所（920）**，也**不含新版创业板代码段 302**。
（实测库里 `920` 有 62,379 行、`302` 有 243 行，两者都不在白名单内。）

> ⚠ 这一条曾经实现成「按组合范围过滤后的行数」，导致 ready 系统性偏低。
> 对「主板+创业板」范围实测：241 个交易日里 **76 天档位不同、26 天强平判定相反、
> 20 天禁止开新仓**。修正后同一区间回测从 **77.89% → 124.05%**。

## 二、买入规则

### 2.1 四道门，全过才买

一只票要真正买进，必须**依次**通过：

| # | 门 | 判定 | 不通过的后果 |
|---|---|---|---|
| ① | **候选结构门** | `isLowBuyCandidate`（见 2.2） | 不进候选池 |
| ② | **广度允许开新仓** | `ready >= 1000`（slow1000 档第一档阈值） | 当天不建任何新仓 |
| ③ | **指数闸门** | 见 2.3 | 当天不建任何新仓 |
| ④ | **有额度 + 有层数** | `desired > 已持仓数`，且 `free_layers > 0` | 不建仓 |

### 2.2 候选结构门（`isLowBuyCandidate`）

以下条件**全部满足**才算候选：

1. **均线值有效**：`Open / Close / Ma5 / Ma20 / Ma30 / Ma60 / Ma120 / Ma250 /
   Ma5Prev / Ma250Prev` 全部 `> 0`
2. **多头排列**：
   - `Ma120 > Ma250` 且 `Ma250 > Ma250Prev`（长周期向上）
   - `Ma30 > Ma60` 且 `Ma20 > Ma30`（中周期多头）
3. **贴近 MA20/MA30 之间（低吸区间）**：
   - `Close >= Ma30 * 0.975`
   - `Close <= Ma20 * 1.04`
4. **MA5 拐头**：`Ma5 < Ma30` 且 `Ma5 > Ma5Prev`（刚从下方转上）
5. **当日阳线**：`Close > Open`
6. **20 日涨幅不超**：`StockReturn20D <= 25`
   （注意是**个股自身**的 20 日收益，**不是**相对强弱 `relative_strength_20d`）
7. **20 日回撤落在允许区间**：`dd20`（`DrawdownFromHigh20`）在

   | 就绪数 | dd20 允许区间 |
   |---|---|
   | `ready >= 1200` | **[-18, -1.5]**（紧档：只接小幅回调） |
   | `ready < 1200` | **[-28, -3]**（宽档：允许更深回调） |

   > 直觉上反了：广度**好**的时候反而要求回调**浅**。这是原实现的意图 ——
   > 广度好说明市场强，强势里只接浅回调。

### 2.3 指数闸门（`LowBuyIndexEntryAllowed`）

指数：**创业板指 `399006.SZ`**；长周期比对基准：**沪深300 `000300.SH`**

```
长周期就绪(long_cycle_ready) =
        指数收盘 > 指数MA250
    且  沪深300收盘 > 沪深300的MA250
    且  指数MA250 > 0
    且  沪深300的MA250 > 0

假热度(hot) = ready >= 2400 且 不是长周期就绪

允许开新仓 = 指数数据可取到(gate.Ready)
         且 指数收盘 > 指数MA20
         且 指数收盘 > 指数MA60
         且 不是假热度
```

**取不到指数数据 → 直接关闸**（"取不到就关"）。

**含义**：广度很热（≥2400）但长周期还没修复时，属于**弱周期假热度**，此时关闸不追高。

### 2.4 买多少：动态目标只数 + 建仓层数

**（a）动态目标只数**

```
目标数 = max(0, min(期望档位, target_position_count, max_stock_count))

slow1000 档（默认）的期望档位：
    ready < 1000          → 0   （完全不开新仓）
    1000 <= ready < 1500  → 1
    1500 <= ready < 2000  → 2
    2000 <= ready < 2600  → 3
    ready >= 2600         → 5

conservative1200 档（star 范围用）：
    < 1200 → 0 | >=1200 → 1 | >=1800 → 2 | >=2400 → 3 | >=3200 → 5
```

**（b）建仓层数（每只占几层）**

```
建仓层数 = clamp(total_layers / 目标数, 1, total_layers)
         = 0   若目标数 <= 0
```

> ⚠ 分母是**动态目标数**，不是配置里的 `target_position_count`。
> 目标数越小 → 建仓层数越大 → **单只权重越大**。
> 例如 `total_layers = 10`：目标 5 → 每只 2 层（20%）；目标 2 → 每只 5 层（50%）；
> 目标 1 → 每只 **10 层（100%）**。

**（c）额度与层数上限**

```
允许额度 = min(total_layers, 目标数 * 建仓层数)
实际建仓层数 = min(建仓层数, free_layers)      # free_layers = 可用层数
```

**（d）每层预算（回测/实盘一致）**

```
每层预算 = 总资产 * 该次建仓层数 / total_layers
买入可用额 = min(现金, 每层预算)
```

**（e）每日最多新建只数**

```
LowBuyDailyMaxNewAdds = 1
```

即**一天最多新建 1 只**（即便目标数还有空位）。

**（f）单股层数上限**

```
maxLayersPerStock = min(10, total_layers)      # 低吸档
```

### 2.5 买入排序（`amount_entry`，main_gem 档）

```
成交额 DESC  →  优先级分 ASC  →  代码 ASC
```

优先级分由 `LowBuyEntryScore` 算出（依赖当前 ready 与成交额排名）。
其它档不同：`gem` / `gem_star` 用 `deep_amount`（更偏深度回调），
`star` 用 `board_norm_amount`。

## 三、卖出规则

### 3.1 常规退出（`LowBuyExitReason`，两条件）

**① 结构失效（跌破 MA30 缓冲线）**

```
Close < Ma30 * ExitMa30Ratio
→ 退出，理由「跌破MA30*0.96，低吸结构失效」
```

`ExitMa30Ratio` **按范围档不同**：

| 范围档 | `exit_ma30_ratio` |
|---|---|
| **main_gem（主板+创业板，默认）** | **0.96** |
| main / all / main_star / gem / star / gem_star | 0.94 |

> ⚠ 只有 `main_gem` 是 **0.96**，其余都是 0.94。写成 0.96 会让止损线**提前**、
> 更早清仓。用户当前范围 `{"markets":["main","gem"]}` → 取 **0.96**。

**② 利润保护（从高点回撤）**

```
若 建仓以来最高涨幅 >= ProtectStartPct
且 当前价相对最高价回撤 <= -ProtectRetracePct
→ 退出，理由「低吸浮盈N%后从高点回撤M%，保护利润」
```

**触发参数按范围档**：

| 范围档 | 浮盈起点 | 回撤容忍 |
|---|---|---|
| **main_gem（当前）** | **未启用** | **未启用** |
| gem_star | 30% | 10% |
| 其余档 | 未启用 | 未启用 |

> ⚠ **main_gem 档没有配利润保护**（`ProtectStartPct = 0`），所以这条对当前组合
> **不会触发**；唯一常规退出就是「跌破 MA30*0.96」。

### 3.2 强制清仓（广度不足）

```
若 ready < LowBuyClearReadyCount (900)
→ 清仓（所有持仓）
```

理由文案形如：`低吸广度不足（就绪数 882 < 900），清仓`。

> ⚠ 这是低吸**最容易被误伤**的一条：ready 算错（样本集偏小）会让它频繁触发。
> 实测库里 2026-06-08 原口径 1064（≥900，不清）vs 错口径 882（<900，清）——
> 后者把一笔 **+58.4%** 的盈利单强平了。

### 3.3 低吸**不参与**的动作

为避免与其它策略的逻辑冲突，低吸档**明确屏蔽**了这些动作：

| 动作 | 说明 |
|---|---|
| **配对换股** | 不做「A 换 B」的配对比较 |
| **急涨兑现** | 不因短期急涨而止盈 |
| **overflow 补位** | 不做补位买入 |
| **广度闸门改写行** | 不套用通用的市场广度闸门（低吸用自己的 `ready` 闸门） |
| **严重结构破坏（severe_break）** | 恒为 false |
| **需要反弹才卖（needs_rebound_exit）** | 恒为 false |

> 通用策略的 `_apply_market_breadth_entry_gate`（70 分 / 20 只 / universe≥100）
> 对低吸**不生效** —— 两边都是空操作。

## 四、仓位规则小结

| 项目 | 规则 |
|---|---|
| 分母 | `total_layers`（组合字段，默认 **10**） |
| 每层 | 总资产的 `1/total_layers` = **10%** |
| 目标只数 | 由 `ready` 档位决定，再被 `target_position_count` / `max_stock_count` 夹住 |
| 单只层数 | `total_layers / 目标只数`（截断取整，至少 1） |
| 单只上限 | `min(10, total_layers)` 层 |
| 总仓位 | 目标数 × 单只层数 ≤ `total_layers` |
| 每日新建 | 最多 **1** 只 |
| 加仓 | `add_layer`（低吸档：受 free_layers 限制） |
| 减仓 | `reduce`（按层数比例卖，不足 1 股时至少卖 1 股） |

### 实机例子（用户当前组合：target=5, max_stock=5, total_layers=10）

| | ready | 档位 | 目标数 | 单只层数 | 单只权重 | 最多几只 |
|---|---|---|---|---|---|---|
| 2025-10-27 | 1990 | 1500~2000 | **2** | `10/2 = 5` | **50%** | 2 |
| 若 ready 达 2600+ | 2600 | ≥2600 | **5** | `10/5 = 2` | 20% | 5 |
| 若 ready < 1000 | 900 | <1000 | **0** | — | — | **禁止开新仓** |
| 若 ready < 900 | 880 | — | — | — | — | **强制清仓** |

> 结论：**ready 越高 → 目标只数越多 → 单只越分散、总仓位越接近满仓**；
> ready 越低 → 越集中（甚至单只 100%），低到 900 以下则清仓离场。

## 六、依赖的数据（缺了会静默算不出）

| 数据 | 用途 | 缺失后果 |
|---|---|---|
| **`daily_bars`**（个股日线） | 算均线、候选、评分 | 该段无法评分（`根数<30` 跳过） |
| **`index_bars`**（指数日线） | **交易日历**、RS 基准、指数闸门 | **回测日历直接被截断** |

> ⚠ 实机踩过：`index_bars` 只覆盖 2023-10-09 起（728 行）时，
> `tradingDates(20221012, 20261012)` 只返回 **728** 天 ——
> 之前的日子**根本不在日历里**，表现为"补了个股数据却还是算不出那一年"。
> **做长区间回测时 `daily_bars` 与 `index_bars` 两个数据集都要补。**

另需注意**预热窗口**：评分需要约 320 个交易日的历史，所以回测/回填的
实际取数起点要往前推（如 2022-10-12 起算，需 2021-06 起的数据）。

## 七、快速对照表：一句话理解每道判定

| 判定 | 一句话 |
|---|---|
| `ready` | 全市场有多少只票站在 MA60 上方且 MA20 在 MA60 上方 |
| 候选 | 长中周期多头 + 回踩到 MA20/MA30 之间 + MA5 拐头 + 当日阳线 |
| 可开仓 | ready ≥ 1000 且 创业板指站上 MA20/MA60 且 不是弱周期假热度 |
| 目标数 | ready 每跨过 1000/1500/2000/2600 就多开一档，最多 5 |
| 每只仓位 | 10 / 目标数 层，即总资产的 `层数 × 10%` |
| 每日新建 | 最多 1 只 |
| 止损 | 跌破 `MA30 × 0.96`（main_gem 档） |
| 清仓 | ready < 900 |
| 不参与 | 配对换股、急涨兑现、补位、通用广度闸门 |

# 缠论辅助组合回测 · 实验计划

> 目标：用**单元测试 + 受控实验**回答一个问题——
> 在组合管理的「组合回测」里，把缠论买卖点作为**辅助信号**叠加到**趋势低吸**策略上，
> 买入时遇到**二买 / 三买确认**加 1 / 2 层、卖出时遇到**一卖 / 二卖 / 三卖确认**分批分层减仓，
> 能不能**提高收益率、降低最大回撤**？
>
> 状态：**已完成**（2026-10-20）。实际结果、对比与限制见 [缠论辅助组合回测_结果.md](缠论辅助组合回测_结果.md)；
> 原始数据见 [缠论辅助组合回测_原始结果.json](缠论辅助组合回测_原始结果.json)。本文件保留为**事前计划**，
> 便于核对「判定标准是否在跑之前就写死」。
>
> 日期：2026-10-20
> 范围：只测「趋势低吸」（`trend_pullback_low_buy`），不改变原策略评分与选股逻辑。

---

## 一、现状与切入点

| 层 | 代码 | 作用 |
|---|---|---|
| 选股/评分 | `internal/score`（`BuildRotationPlan`） | 趋势低吸产出 `add / add_layer / reduce / clear / replace_in` 等动作与层数 |
| 回测引擎 | `internal/backtest`（`Engine.Run`） | T 日收盘出计划，T+1 开盘执行；按层分配预算（每层 = 总资产 / 总层数） |
| 缠论 | `internal/chanlun`（`Analyze`） | 日线级别输出一/二/三买、一/二/三卖，带 `candidate/triggered/confirmed/invalid/expired` 状态机与确认日期 |
| 服务编排 | `internal/service/backtest.go` | 取评分 → 贴信号 → 取日线 → 组装 `PlanBuilder` → 跑引擎 → 落库 |

关键事实：

1. **引擎只认计划**。要让缠论影响回测，最小侵入点是给 `PlanBuilder` 加一层「计划装饰器」，
   不改引擎、不改评分。这样基线与实验组**共用同一套选股和撮合**，差异只来自缠论。
2. **层就是仓位**。`layerBudget = 总资产 × 层数 / 总层数`，加 1 层 = 多约 10% 总资产；
   减 1 层 = 卖掉约 1/当前层数 的持股。因此「加 1/2 层」「分 1/2/3 层卖」可以直接落到引擎语义里。
3. **不能有未来函数**。缠论信号必须在「计划日收盘」时点用**截断到当日的 K 线**重新分析，
   不能先对全区间分析再按日期回填——后者会把后来才确认、甚至后来已失效的信号当成当时有效。

## 二、叠加层设计（`internal/chanlunassist`）

### 2.1 信号口径

- 分析级别：**日线**（`chanlun.LevelDay`），与缠论面板默认一致。
- 只接受 **`confirmed`（确认）** 状态；`candidate/triggered` 默认不算（可用 `AllowTriggered` 打开）。
- **新鲜度**：确认日距计划日不超过 `BuyFreshBars / SellFreshBars` 个交易日（默认 10），
  避免拿一个月前的信号解释今天的加仓。
- 同一类型多条信号取**综合分最高**的一条；买入按 `三买 > 二买` 取最强，卖出按 `三卖 > 二卖 > 一卖`。
- 结构矛盾（`Signal.Conflict`）默认剔除。

### 2.2 买入：确认二买 / 三买加层

| 触发 | 默认加层 | 约束 |
|---|---|---|
| 确认 **二买** | +1 层 | 仅作用于当日计划里的 `add / add_layer / replace_in` 行 |
| 确认 **三买** | +2 层 | 单股总层数不超过 `MaxLayersPerStock`（默认 7 = 低吸基准 5 层 + 2；引擎另有硬上限） |
| 同股同日同时有确认卖出信号 | 不加层 | 风险优先，宁可错过不加仓 |
| 同一信号（类型+确认日） | 只加一次 | 避免连续多日重复加层 |

加层后的 `TargetLayers / LayersDelta / Reason` 一并改写，成交流水里能看到「缠论三买加2层」，
便于事后归因。

### 2.3 卖出：确认一卖 / 二卖 / 三卖分批减仓

| 触发 | 默认减层 | 说明 |
|---|---|---|
| 确认 **一卖** | -1 层 | 1 层仓位时等价于清仓（无法卖半层） |
| 确认 **二卖** | -1 层 | 与一卖同向叠加时按「更激进者」取，不重复扣 |
| 确认 **三卖** | -2 层 | 目标层数降到 0 即为清仓 |
| 同日多信号 | 取最强 | 三卖 > 二卖 > 一卖 |
| 同一信号（类型+确认日） | 只减一次 | 避免连续多日阴跌被「同一卖点」反复砍 |
| 基计划已清仓 / 换出 | 不重复处理 | 只做「更保守」的补充，不与其对冲 |

### 2.4 明确不做的事

- 不改选股、不改评分、不改止盈止损、不改仓位总额度公式。
- 不用缠论**创造**新买点：只在原策略本来就要买的时候决定「加不加层」。
- 不做杠杆：加层后仍受现金约束，买不起就按可用现金成交（与引擎现有行为一致）。

## 三、实验设计

### 3.1 三层验证

| 层 | 类型 | 目的 | 数据 |
|---|---|---|---|
| L1 规则单测 | `go test ./internal/chanlunassist` | 加层/分层/上限/去重/组合关系是否严格按设计 | 构造计划 + 假信号提供器 |
| L2 因果性与端到端 | 同上（engine 级） | 信号只用截断 K 线；叠加后净值/回撤确实变化 | 合成行情（受控，非业绩） |
| L3 真实数据对照 | `go test ./internal/service -run TestChanlunAssistRealBacktest` | **主证据**：同一组合、同一区间、同一撮合，基线 vs 叠加 | 本机 `bin/portfolio.db` 副本 + 本地数据湖 |

### 3.2 真实数据实验口径

- 组合：`pf_1791522403274487100_0002`（`trend_pullback_low_buy`，主板+创业板，目标 5 只 / 10 层）。
- 区间：默认最近 2 年（20241014–20261019），测试可用环境变量覆盖。
- 只读副本：先把 `portfolio.db` 复制到临时目录，实验只写副本，绝不碰真实库。
- 三条曲线：
  1. **基线**：不加缠论（现有回测）。
  2. **仅卖出分层**：买入不变，只叠加一/二/三卖减仓。
  3. **买入加层 + 卖出分层**：完整方案。
  4. （可选）**仅买入加层**：只加层、不提前卖。
- 同一区间、同一初始资金（10 万）、同一手续费/滑点/印花税、同一份评分与日线。
- 指标：总收益、年化、最大回撤、Calmar、Sharpe、成交笔数、胜率、平均持仓天数、
  平均仓位比例、最终净值；另记录缠论事件次数与加/减层数。

### 3.3 判定标准（事前写死，避免事后找理由）

- **提高收益**：完整方案总收益 > 基线，且不是靠单笔运气（同时看胜率/平均盈利）。
- **降低回撤**：完整方案最大回撤 < 基线；若收益更高但回撤也更高，则只算「收益增强」不算「风险改善」。
- **可解释**：差异能由缠论事件解释（加层集中在二/三买、减仓集中在一/二/三卖），
  且交易流水里能逐笔对上。
- **稳健性**：若信号极少（例如两年 < 5 次加层），结论只能记为「样本不足，未观察到显著差异」。

### 3.4 已知限制（必须写进结论）

1. 缠论实现是**本项目的规则化实现**，不是唯一正确的缠论；结论只对该实现成立。
2. 日线级别信号频率低，两年样本可能不足以做统计显著性检验；不宣称「显著」。
3. 加层会提高单股集中度，收益/回撤的改善可能来自「仓位更重」而非「选时更好」，
   因此必须同时给出「仅卖出」对照。
4. 数据湖价格为**复权后的日线**，与回测撮合价同源；除权日的名义金额差异仍按既有引擎处理。
5. 回测不含涨跌停/停牌无法成交的精细约束（引擎现状），极端行情下结果偏乐观。

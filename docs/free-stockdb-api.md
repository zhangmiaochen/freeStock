# free-stockdb HTTP 接口速查（实测整理）

> 本文是本项目在对接过程中对 free-stockdb 本地 HTTP 服务的**实测记录**，
> 用于说明 `internal/stockdb/` 里那些调用为什么这么写。
> 上游项目：<https://github.com/zhangmiaochen/free-stockdb>，文档：<https://dns.novapi.cc>

## 1. 基本形态

| 项 | 值 |
|---|---|
| 默认地址 | `http://127.0.0.1:7899` |
| 请求 | `GET /?cmd=<命令>&t=<表名>&k1=<一级键>&k2=<二级键>` |
| 响应 | **MessagePack**，`Content-Type: application/x-msgpack` |
| 跨域 | 响应带 `Access-Control-Allow-Origin: *` |
| 配置文件 | `stockdb.conf`（默认 `ip: 127.0.0.1` / `port: 7899`） |

响应**不是 JSON**。官方 `调用方式/http/http_api.py` 里的 `z.json()` 对当前版本不成立；
同目录的 `http_js.js`（WPS 宏）同样按 JSON 解析。实际对接必须解码 MessagePack。

## 2. 三个命令

| cmd | 返回 |
|---|---|
| `get` | 命中单个键时返回值本身（如一条日K字典）；未命中返回**空数组** `[]` |
| `vals` | 返回值的数组 |
| `keys` | 返回**键名**数组，形如 `["日k:600633:20000107", ...]` |

## 3. 键表达式

`k1` / `k2` 支持表达式，实测结论：

| 表达式 | 含义 | 备注 |
|---|---|---|
| `all:` | 全部 | |
| `key:600633` | 指定一级键 | |
| `fwd:20260901,20260930` | 区间查询 | **返回顺序为倒序（最新在前）** |
| `20260625` | 精确点查询 | 等价于单键 |
| `20260901<20260930` | *看起来*是区间 | ⚠️ **实测未生效，返回了全部 5445 条历史**，不要用 |
| `N` | 无边界占位 | `keys 日k key:000001 N` → 该股全部日期键 |
| `[-3:]` / `[:5]` | 截取 | ⚠️ 拼在 `k2` 后实测无效，仍返回全量 |

### ⚠️ 最重要的坑：`k1=*`

```
GET /?cmd=vals&t=日k&k1=*&k2=20260930
```

`k1` 用 `*` 时 **`k2` 过滤会被忽略**，实测一次返回 **6.17 GB**（`cmd=keys` 也有 417 MB）。
永远不要这样查"某天全市场行情"。需要全市场快照时，请逐只股票做点查询
（本机实测 7500 只、48 并发约 1 秒）。

## 4. 表结构

### `股票代码`
返回 `map[首位数字][]6位代码`：

```json
{"0": ["000001", ...], "1": ["159001", ...], "3": ["300001", ...],
 "5": ["501001", ...], "6": ["600000", ...], "9": ["920001", ...]}
```

本机实测分布（共 7563 个代码）：

| 桶 | 数量 | 前缀构成 |
|---|---|---|
| `0` | 1493 | 002(921) 000(415) 001(115) 003(42) |
| `1` | 995 | 159(683) 16x(约 280) 180(27) |
| `3` | 1397 | 300(938) 301(458) 302(1) |
| `5` | 1058 | 5xxxxx 各类基金 |
| `6` | 2311 | 600(754) 603(612) 688(606) 601(225) 605(113) 689(1) |
| `9` | 309 | 920(309) |

### `日k:代码:日期`
一条记录（21 个字段）：

```json
{"date":20260625,"code":"600633","name":"浙数文化","open":10.45,"high":10.62,
 "low":10.37,"close":10.45,"pre_close":10.52,"volume":18031500,"amount":189010000,
 "turnover":1.42,"pct_chg":-0.67,"amplitude":2.38,"is_st":false,"vol_ratio":0.9,
 "total_share":1268074472,"float_share":1268074472,
 "total_mv":13251000000,"float_mv":13251000000,"pe_ttm":22.5,"pb":1.3}
```

- **`name` 字段就在这里**，所以股票名称不需要额外的表。
- 单条点查询约 320 字节。
- 停牌/退市标的在最新交易日可能没有记录 → 需要回退查询。

### `分钟k:代码:14位时间戳`
字段较少：`date / code / open / high / low / close / volume / amount`。

### `板块*`
返回 `[[键名, 板块对象], ...]`，实测 1337 条、856 KB：

```json
{"code":"801170.SL","name":"交通运输","source":"sw","type":"sw_1",
 "group":"申万行业指数列表","category":"申万一级",
 "symbols":["000088","000089", ...]}
```

分类分布：

| category | 数量 | source |
|---|---|---|
| 申万一级 | 28 | sw |
| 申万二级 | 104 | sw |
| 申万三级 | 227 | sw |
| 概念 | 978 | ths |

`symbols` 给出了板块 → 成分股，反过来即可得到**个股 → 所属行业**。

### 其他已知表
`复权`（复权因子，含 `cum` 字段）、`退市*`、`资金流`、`分钟k`。

## 5. 性能实测

| 操作 | 耗时 |
|---|---|
| `股票代码`（53 KB） | ~5 ms |
| `keys 日k key:000001 N`（6321 个键，114 KB） | ~26 ms |
| `板块*`（856 KB，1337 条） | ~20 ms |
| 7500 只股票最新日 K 点查询（48 并发） | **~1.0 s** |

数据库最新交易日可由任一股的 `keys` 结果取最大值得到（本机为 `20260930`）。

## 6. 本项目采用的策略

1. `股票代码` 拿到全部代码 → 按代码前缀判定市场（见 `internal/market`）
2. 用 `000001` / `600519` 的 `keys` 推断最新交易日
3. 对每只股票做**点查询** `get 日k:代码:最新日期`（48 并发）
4. 未命中的（停牌等）再用 `vals 日k key:代码 fwd:最新日期-45天,最新日期` 回溯补抓，
   取第一条（区间倒序，最新在前）
5. `板块*` 一次性取回，按 category 在前端建立"个股 → 行业"倒排索引

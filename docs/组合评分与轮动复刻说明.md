## 1.1 `stock_strength_history` 的写入链路

**表结构**：`portfolio_migrations.py:73-146`，主键 `(trade_date, strategy_id, ts_code)`；后续 ALTER 补列见 `portfolio_migrations.py:347-383`。

**只有两个写入函数**（全项目 grep 确认）：

| 入口 | 位置 | 行为 |
|---|---|---|
| `PortfolioService.refresh_latest()` | `portfolio_service.py:660` | 用 `_build_strength_history_frame(最新日, 最新日, ...)` 生成，`_write_batches(..., replace=True)`（`:674`）——按主键 upsert |
| `PortfolioService.refresh_backfill(start,end)` | `portfolio_service.py:690` | 先 `delete_rows` 删除区间（`:716`），再 `_write_batches(..., replace=False)`（`:717`） |

CLI 触发：`portfolio_refresh.py --latest` / `--backfill --start-date --end-date`。

**字段计算总函数**：`PortfolioService._build_strength_history_frame()`（`portfolio_service.py:1616-2241`）。它分 8 步：

1. `_load_market_frame`（`:1250`）拉全市场日线 → 均线/收益/量比/高低点（`:1699-1782`）
2. `build_drawdown_repair_features`（`portfolio_strategy.py:339`）→ `repair_*` 5 列
3. 基准指数 → `benchmark_return_20d`（`:1784`）、`relative_strength_20d`（`:1826`）
4. `build_market_state_cache`（`volume_price_market_state.py:227`）→ `market_state` / `market_state_label`
5. 创业板指+低吸闸门 → `low_buy_*`（`:1640-1693`、`_apply_low_buy_hot_breadth_gate` `:122`）
6. 行业相对强度、成交额/换手/行业排名分位（`:1857-1867`）
7. 研究快照（`:1869`）与板块强度（`:1888-1933`）
8. 计算 5 个"基础分"（`:1968-2036`），再对每个策略调用 `apply_strategy_scores`（`portfolio_strategy.py:407`）得到最终 5 分项 + 调整分 + 总分（`:2159-2241`）

### 1.1.1 复权口径（重要）

`_load_market_frame` 直接查询 `bars_daily` 的原始 `open/high/low/close`（`market_data.py:2110` 的 `_query_daily_rows_df`），
**全链路没有任何 `adj_factor` / `qfq` / `hfq` 处理**；`bars_daily.adjustflag` 虽被 SELECT 出来但从未使用（该表默认 `"3"` = 不复权）。
→ **均线、收益率、回撤、相对强度全部基于不复权收盘价**。Go 侧若用前复权数据，结果会有除权日偏差。

### E. 修复能力 `repair_*`（`portfolio_strategy.py:339-404`）

参数：`drawdown_threshold = -10.0`，`recovery_window = 40`。**逐股票**循环：

```text
# 1) 事件识别（i 从 0 到 n-41）
if high120[i] > 0 and close[i] > 0:
    dd = (close[i]/high120[i] - 1) * 100
    if dd <= -10.0 and (i - last_event) >= 10:      # 同类事件间隔 >=10 个交易日
        last_event = i
        window = close[i+1 : i+41]
        recovered     = exists(window >= high120[i] * 0.98)
        recovery_days = 首个命中下标 + 1，否则 40
        new_high      = max(window) >= high120[i] * 1.02
        known_at = i + 41                            # ← 防未来函数：41 个交易日后才计入
        if known_at < n: 累计到 known_at 行
# 2) 累计值（只增不减）
repair_event_count            = 累计事件数
repair_recovery_probability   = 累计恢复数 / 累计事件数 * 100      # 事件数=0 → 0
repair_avg_recovery_days      = 累计 recovery_days / 累计事件数    # 事件数=0 → 0
repair_new_high_probability   = 累计新高数 / 累计事件数 * 100
# 3) 修复能力分
speed_score    = clip((40 - avg_days) / max(1, 40 - 8), 0, 1)
repair_ability_score = clip(prob_ratio * 8.0 + speed_score * 4.0 + new_high_ratio * 3.0, 0, 15)
#   注意 prob_ratio 用的是 0..1 原始比例（未乘 100）
# n <= 41 的股票：以上 5 列全为默认 0
```

`near_term_repair_score` 不是这里算的，它是"基础修复分"（见 H 节末）。

### G. 市场状态 `market_state` / `market_state_label`（`volume_price_market_state.py:227-330`）

**基于全市场"市场宽度"，不是基准指数趋势。** 输入 = 当日全市场 `pct_chg` 与 `amount_yuan`。

```text
# 宽度日线（build_market_width_daily）
按 trade_date 聚合：avg_pct = mean(pct_chg)
                    up_ratio = mean(pct_chg > 0)
                    down_ratio = mean(pct_chg < 0)
                    amount = mean(amount_yuan)
                    count = n

# 对每个 trade_date td：取 td 及之前最多 80 个交易日窗口；<20 天 → range
proxy_close = cumprod(1 + avg_pct/100)                      # 窗口内
recent = 窗口最后 20 行；prev = 窗口倒数 21~40 行（不足 40 时取前 len-20 行）
proxy_ret20   = (recent_proxy[-1]/recent_proxy[0] - 1) * 100
higher = recent_high > prev_high and recent_low > prev_low
lower  = recent_high < prev_high and recent_low < prev_low
amount_growth = (近5日 amount 均值 / prev 近5日 amount 均值 - 1) * 100

bull_score = 45 + 25*(higher) + (20 if proxy_ret20>=5 else max(0, proxy_ret20*2))
             + 15*(近5日 up_ratio>=0.55) + 10*(amount_growth>=5)
bear_score = 45 + 25*(lower)  + (20 if proxy_ret20<=-5 else max(0, |min(proxy_ret20,0)|*2))
             + 15*(近5日 down_ratio>=0.55)

elif bear_score >= 75 and bear_score >= bull_score + 10: state = "bear"
else:                                                    state = "range"
```

### I. 五个基础分（`:1968-2036`，"基础分"仅 `trend_growth` 会直接使用）

```text
# trend_base_score  (0~30)
8*(close > ma20) + 8*(ma20 > ma60) + 6*(ma60 > ma120) + 4*(ma120 > ma250)
+ 2*(ma20 > ma20_lag5) + 2*(ma60 > ma60_lag10)                    → clip 0..30

breakout_gap_pct = (close - prev_high60)/prev_high60 * 100        # prev_high60<=0 → 0

+ 4*(close>=ma20 and volume_ratio_20<=1.15 and -18<=drawdown_120<=-3)
+ clip(best_model_win_rate/100, 0, 1) * 2                          → clip 0..20

# rs_base_score (0~20)
clip((relative_strength_20d + 10)/20, 0, 1) * 14
+ clip((industry_return_20d - benchmark_return_20d + 10)/20, 0, 1) * 6   → clip 0..20

# capital_base_score (0~15)
clip(amount_rank_pct,0,1)*7 + clip(turn_rank_pct,0,1)*4
+ clip((volume_ratio_20 - 0.8)/1.2, 0, 1)*2 + clip(industry_strength_pct,0,1)*2  → clip 0..15

# near_term_repair_score (0~15)  ← 入库列名 near_term_repair_score
clip(rebound_from_low_60, 0, 1)*6
+ clip((20 + drawdown_from_high_120)/20, 0, 1)*4
+ 2*(close > ma20) + 1.5*(close > ma60)
+ clip((close/max(prev_high60,1e-9) - 0.95)/0.08, 0, 1)*1.5        → clip 0..15
```

## 3.1 换股（replace）配对逻辑（`:2173-2280`）

```text
for hold in held_ranked:                       # 按 total_score ASC 排序 → 从最弱持仓开始
    if len(replacement_pairs) >= policy.max_replace_count: break
    if 低吸策略: continue                        # 低吸永不参与换股配对
    quick_profit_take = should_quick_profit_take(...)   # 非低吸才计算
    if quick_profit_take or repair_hold(恒False): continue
    if not force_clear and not replace_allowed and not rebound_ready: continue
    for cand in candidate_ranked:              # 已按候选优先级排序
        if cand.ts_code in used_candidate_codes or == hold_code: skip
        if not candidate_quality_ok(cand, policy, replacement_mode=True): skip
        cand_score, hold_score
        total_gap = cand_score - hold_score
        if force_clear:                        # 强制清仓型（结构破坏/超跌失败）
            if cand_score >= policy.ready_score: 选中; reason="{结构破坏}，切换到更强候选"; mode="full_replace"; break
            continue
        required_gap = dynamic_replace_gap(hold, cand, policy) = max(20.0, policy.replace_score_gap)
        if cand_score < policy.ready_score or total_gap < required_gap: continue
        if rebound_ready:                      # 破位反弹阳线
            选中; reason="破位反弹后切换到更强候选"
            mode = "full_replace" if (hold_layers<=1 or state=="bull") else "partial_rotate"; break
        if not replace_allowed: continue
        选中; reason = replacement_reason(...)
        if hold_layers>=2 and projected_name_count<max_stock_limit and state!="bull":
            mode="partial_rotate"; projected_name_count += 1
        else:
            mode="full_replace"
        break
```

**配对规则小结**
- 一个候选只能用一次（`used_candidate_codes`）；一个持仓最多配一个候选。
- 全局最多产出 `max_replace_count` 对。
- `replace_score_gap` 参与方式：`required_gap = max(20.0, policy.replace_score_gap)`，因为两个来源（策略配置 / 轮动策略）取值都 ≥ 20，**实际上恒为 `max(20, 20..26)` = 20~26 分**，且 `force_clear` 分支完全跳过 gap 校验（只要 `cand_score >= ready_score`）。
- `max_replace_count`：配对阶段的硬上限（`break`）。
- `partial_rotate` = 只减 1 层（不减名），`full_replace` = 换出全部层数。
- `replacement_reason`（`:1547-1560`）：在 `{趋势与结构更优: |Δtrend|+|Δstructure|, RS优势更强: |Δrs|, 修复能力更强: |Δrepair|, 综合评分显著领先: max(0, cand-hold)}` 中取最大值对应的字符串。

## 3.3 加仓 / 建仓层数

```text
# initial_entry_layers(row, policy, free_layers, remaining_slot_need)   (:1438-1540)
低吸策略                 → min(2, max_layers_per_stock)
max_layers_per_stock<=1  → 1
expert_simulation        → 1
oversold_rebound         → min(2 if total_score>=70 else 1, max_layers)
trend_growth 且 range    → min(2, max_layers)
bull_ready (state=bull, signal buy, age<=2, score>=80, trend>=22, struct>=12, rs>=10,
            signal_score>=68, close>=ma20*0.998, close>=ma30*1.002, -16<=dd120<=4, 非过热) → 2
range_ready(state=range, age<=2, score>=84, trend>=23, struct>=13, rs>=11, signal_score>=74,
            close>=ma20*0.99, close>=ma30*0.995, -18<=dd120<=-1, 非过热)               → 2
capacity_pressure = free_layers>0 and free_layers>=max(2, remaining_slot_need+1)
                    and free_layers/desired_total_layers >= 0.2
bull_fill_ready (bull, age<=4, score>=77, 21/11/9, signal>=66, ma20*0.995, ma30*0.998, -20<=dd120<=4)
range_fill_ready(range, age<=2, score>=81, 21/11/9, signal>=70, ma20*0.986, ma30*0.992, -20<=dd120<=-1)
if capacity_pressure and (bull_fill_ready or range_fill_ready) → 2
else → 1
# 低吸建仓层数单独用 _low_buy_entry_layer_count(total_layers, target) = clip(int(total/target), 1, total)
```

**加层（`add_layer`）**（`:2533-2573`）：仅非低吸、且 `layer_room = desired_total_layers - planned_layers_after_add > 0`；
候选 = `action=="keep"` 且 `can_add_second_layer(row, policy)` 的持仓，排序键 `(-total_score, -structure_score, -repair_score, ts_code)`；
逐只 `target = min(max_layers_per_stock, layers+1)`，命中则把该持仓行改写为 `add_layer`，reason="结构未破，回踩关键均线后企稳，加1层"，`decision_state="repair_add_second_layer"`。

`can_add_second_layer`（`:1376-1409`）= 非低吸 + `layers < max_layers_per_stock` + 非结构破坏 + 非 `needs_rebound_exit` + 非过热 + `is_strong_stock_for_layering` +（`ma20` 或 `ma30` 的 `_is_confirmed_pullback_rebound` 或 `_is_bull_trend_continuation_add_signal`）；
`layers>=2` 时额外要求 `holding_days>=3` 且 `pct_chg>=0.3`，且只认 `ma20_confirmed or continuation_add`。

`is_strong_stock_for_layering`（`:1293-1356`）关键阈值：
`close < ma30*0.997` 直接否决；`layers>=2` 要求 `state=="bull"`、`score>=max(ready,76)`、`21/12/10`、`rs20>=4`、`close>=ma20*0.995`、`current>=entry*0.995`；
`layers==1` 要求 `score>=max(ready-4,70)`、`trend>=20`、`struct>=11`、`rs>=9`、`rs20>=-1`、`close>=ma20*0.992`、`dd120>=-22`、`profit>=-2.5`、`current>=entry*0.98`，或（`score>=max(ready-2,72) and 21/12/10`）。

## 3.5 `hold_compare` 字段算法（`:2264-2280`）

## 5.5 「一键应用建议」`apply_rotation` 完整流程与副作用

**GUI 侧**（`gui_qt.py:11408-11432`）
1. 未选组合 → 提示返回。无二次确认弹窗（确认语义靠按钮文案：半自动时显示「确认应用建议」，手动组合显示「手动组合不可一键应用」并禁用，见 `:9651-9658`）。
2. 置忙 → 后台线程调 `PortfolioService.apply_rotation(portfolio_id)` → 成功后弹「完成」、刷新总览 + 详情（`load_overview(silent=True)`、`load_detail(..., silent=True)`）。

**服务侧**（`portfolio_service.py:855-980`）
1. `build_portfolio_behavior_config(portfolio_type)`；`allow_apply_rotation == False`（手动组合）→ 抛 `PortfolioDataUnavailableError`。
2. 取最新评分日 `_get_latest_strength_trade_date()` + `_latest_strength_frame(td, strategy_id)`。
3. **副作用 A**：`_rebuild_portfolio_view(pid, td, latest_scores)` → 删除并重写当日 `portfolio_score_snapshot` / `portfolio_candidate_snapshot` / `rotation_signal` / `hold_compare`（`portfolio_service.py:2443-2461`）。
4. 过滤 `is_executable == True` 的 rotation 行；为空 → 报错，不改动任何数据。
5. 遍历 `持仓 ∪ 计划` 的代码并集：
   - `target_layers`：`clear/replace_out → 0`；`reduce/add_layer/add/replace_in → 计划 target_layers`（缺失则保持当前）；其他 → 保持当前。**再 `min(target, 3)`（`max_layers_per_stock = 3` 在这里硬编码，不复用策略配置）**。
   - `layer_delta = target_layers - current_layers`；`layer_delta == 0 且 target<=0` → 跳过该股；`layer_delta != 0` → `changed_count += 1`。
   - **副作用 B**：写一条 `portfolio_position_txn` 流水（`_append_txn`）：`action`=计划动作（无则 add/clear）、`price`=最新 `close_price`（缺失回退持仓 `entry_price`）、`layers_delta`、`weight_delta`、`reason="一键应用调仓建议"`、`source_signal_id="{pid}:{td}:{code}"`、`txn_id` 新建。
   - `target_layers <= 0` → 该股只留流水，不写持仓。
   - 建仓价：加层且原持仓>0 → 加权平均 `(原entry*原层数 + 最新价*层数增量)/目标层数`，`entry_date` 不变；原层数=0 → 用最新价 + `entry_date=td`；否则保持原值。
   - `position_weight = round(layers/total_layers*100, 4)`（`_weight_from_layers`，`:183`）；`total_layers` 来自 `_legacy_total_layers()`（配置默认 10）。
6. `changed_count <= 0` → 报错，不改动持仓。
7. **副作用 C**：`delete_rows("portfolio_position", "portfolio_id = ?")` 全删后 `append_rows` 重写整表（`:967-969`）。
8. **副作用 D**：再次 `_rebuild_portfolio_view` 刷新当日四张快照表。
9. 返回 `{ok, message("调仓建议已应用" / "半自动组合建议已确认并应用"), trade_date, position_count, snapshot}`。

**HTTP 接口**（`fastapi_backend.py`）：
`GET /api/portfolio-manager/portfolios/{id}/detail`（`:6846`）、`GET .../rotation`（`:6909`）、`POST .../apply-rotation`（`:6919`）、`POST /api/portfolio-manager/refresh`（`:6892`）。

2. **`repair_*` 需要 41 个交易日延迟入账**（`known_at = i + 41`）与"同类事件间隔 ≥10 日"，且是**累计值**不是滚动值。
3. **市场状态来自全市场宽度**（`mean(pct_chg)` 的 cumprod 代理指数 + 高低点结构 + 涨跌占比 + 成交额增速），不是沪深300 趋势。
4. **`reduce_score` 是死参数**；`hold_for_rebound_exit` 不是 action 值；`keep` 是兜底而非"稳定"判定。
5. **信号字段不入库**：需要复刻 `pd.merge_asof(direction="backward", tolerance=29)` 的回填，否则 bear 态开仓、信号优先级、溢出补位都失效。
6. **`strategy_adjustment_score` 各策略语义不同**（且 `repair_score` 在 trend_growth 用 `repair_ability_score`，在其它策略用 `near_term_repair_score` 混权），不能抽象成统一权重。
7. **低吸策略在换股阶段被整体跳过**（`if low_buy_strategy: continue`），且 `max_layers_per_stock = total_layers = 10`；`apply_rotation` 又会把层数 clamp 到 3 —— 两者不一致。
8. **`candidate_pool` 落库是全量，Top20/max(80,target*12) 都是展示层/决策层硬编码**。
9. `_low_buy_entry_score_series` 中 `amount_rank = 1 - rank(pct)`（越小越优），而 `board_norm_amount` 模式用的是"同市场内正序分位"，方向相反，注意别抄反。
10. 死常量（未被引用）：`PORTFOLIO_LOW_BUY_MIN_ENTRY_COUNT = 1000`、`PORTFOLIO_LOW_BUY_MIN_AMOUNT_YUAN = 30_000_000.0`（后者在 `apply_strategy_scores` 里以字面量 `30_000_000.0` 出现）。

### 1.2 三个数据陷阱（都是实测撞出来的）

**陷阱 1：报告期数值是年内累计，且 Q4 是全年值。**

实测 600519 归母净利润（亿元）：

```
2023Q1 207.95  2023Q2 359.80  2023Q3 528.76  2023Q4 747.34   ← Q4 = 全年
2024Q1 240.65  2024Q2 416.96  2024Q3 608.28  2024Q4 862.28   ← Q4 = 全年
2025Q4 823.20 = 2025 全年；2025Q4 单季 = 823.20 − 646.27 = 176.93
```

所以正确的 TTM 只需要两段，**不需要把 Q4 减成单季**：

```
TTM(报告期 P) = 上年全年 + 本年至今(P) − 去年同期(P)
```

**验证方式（不是推理，是对拍）**：用 3941 只标的（最新报告期都落在 2026Q2）
比较自建 PE 与数据湖 `valuation_metrics` 里的供应商 `pe_ttm`：

| 口径 | 中位比值（供应商 PE ÷ 自建 PE） | 3% 以内占比 |
|---|---|---|
| **Q4 当全年值**（已采用） | **1.0000** | **99.87%** |
| 把 Q4 当单季再求和 | 偏离 2~3 倍 | — |

这条公式被 `TestTTMUsesQ4AsFullYearNotSingleQuarter`、
`TestSingleQuartersSplitsQ4Correctly` 与 `TestQuarterYoYUsesSingleQuarters` 钉住。

**陷阱 2：同一报告期可能有多条修订，相加会把利润算成两倍。**
必须按 `(symbol, report_period)` 只保留 `announce_date` 最大的一批，且
**整期替换**（逐科目各留各的会让一个报告期里混着两次修订的数值）。
由 `TestBuildAsOfDeduplicatesRevisions` 钉住。

**陷阱 3：`change_date` 是 BIGINT 年份，不是 DATE。**
`share_structure.change_date` 实测形态是 `2026` 而不是 `2026-10-14`，
直接当 DATE 读会得到 1970 年的股本。归一在 `cnlake.StatementDate`。

### 1.3 复权（本项目踩过坑的地方）

数据湖 `daily_bars` 是不复权行情。实测 002594 在 2025-07-29 因 1:3 送转由 337.00
直接变成 111.42；不复权算出来的 MA250 仍是 ~310。后果（本项目既有实测）：

- 除权日 `close < MA30×0.96` 发生率 **44.4%**，平时只有 **29.8%**（1.49 倍）；
- 送转股在其后最长一年内通过不了任何 `close > MA` 条件（候选池 −12.3%）。

本功能的**三条铁律**：

| 用途 | 口径 |
|---|---|
| 收益 / 波动 / 回撤 / 区间涨幅 / 情景收益 | **后复权 hfq**（不复权价 × F(t)） |
| 市值 / PE / PB / PS | **不复权原始价 × 当期股本** |
| 成交量 / 成交额 | 始终原始 |

代码里用**两个不同方法名**强制分开：`Bar.AdjustedClose()`（收益口径）与
`MarketCap(rawClose, shares)`（市值口径），并且结构体同时保留
`Close`（原始）与 `AdjFactor`（因子）。`TestMarketCapUsesRawCloseNotAdjusted`
断言市值不能用复权价。

界面上有两条刻意的设计：

- **缺值一律显示「—」而不是 0**。这个功能里大量字段是"算不出来"而不是"等于 0"
  （分位样本不足、方法不适用、行业成分缺失）。`PE 分位 0%` 读起来像"史上最便宜"，
  而实际含义是"没有历史样本"，所以 `hasPercentile()` 专门区分这两者。
- **所有映射函数入参写成 `unknown`**。引擎侧的 `Rating` / `RiskSeverity` / `ScoreDimension`
  在 Wails 生成的 bindings 里是 TS **enum**，而映射表是"字符串 → 文案"；
  `Record<string, T>` 拿 enum 当索引会取到数字索引签名并报错。入参放宽后
  组件里传 enum、传字符串、传 undefined 都能用，不需要在模板里撒 `as string`。

## 三、与原方案的偏差（如实降级，不假装满足）

| 原方案要求 | 本机实况 | 处置 |
|---|---|---|
| 用现成的"个股与行业历史估值数据" | `valuation_metrics` 只有 5 天 | **自建重建**历史 PE/PB/PS（起点 2021-01-01），界面标明"自建口径" |
| "历史行业归属"避免前视偏差 | `industry_members` 只有 5 个快照 | 当前归属可用；历史行业结论**标注前视偏差并扣置信度** |
| "指数成分股及历史变动" | `index_constituents` 只有 1 个快照 | 5 个指数有当前成分；其余 3 个只给走势类结论 |
| 申万行业分类 | 本机是 `eastmoney` 体系 | 接口按体系无关设计，界面写明体系名 |
| EV/EBITDA | 无"折旧摊销"科目 | 用营业利润近似，仅在高负债率时采用，并把近似口径写进 `Basis` |
| 验收 9（历史可追溯） | 财务/行情可完全满足；行业归属受限 | **部分满足**，`Available`+`Note` 说明 |
| 验收 10（历史验证） | 行业归属受限 → 行业相关验证只能用当前归属近似 | **部分满足**，见方案 §11.1 |

> 关键设计决定：**所有历史相关接口一律 `asOf` 参数化**。数据湖补齐历史成分后，
> 结论自动升级为完全满足，不需要改模型代码。

### 4.1 开发过程中被实测暴露并修掉的 6 个问题

第一版跑通全市场后，输出本身暴露了这些问题（都已在代码里修掉并留了注释）：

| 问题 | 现象 | 修法 |
|---|---|---|
| 行业环境分恒为 50 | 60 个行业的"行业估值环境"分全是 50.0 —— 这个维度变成常数、对排序毫无贡献 | 无历史分位时改用**横截面结构口径**（加权与中位 PE 的背离 + 集中度），见 `industryfallback.go` |
| 评级失去区分力 | 榜上全是"中性"（阈值 80/68/55/42 对实测分布 47~51 太严） | 按实测分布重定分界（72/62/50/38） |
| 现金含量恒为空 | 条件要求"满 4 个季度"，而现金流缺季很常见（实测 capex 5553/5581） | 放宽到"≥2 个季度"，并用 `CashOperateQuarters` 记录完整度供置信度扣分 |
| 安全边际出现 84% 这种荒谬值 | 新华保险 PE 3.8 倍，PB-ROE 用当期 ROE 推出 6 倍 PB → 基准价值是现价 6 倍以上 | ① ROE 超过 25% 的部分只计一半（可维持化）② PB 上限 12→6 倍 ③ 增速外推上限 45%→30% ④ 按期限夹住价值空间 |
| 悲观损失出现 0.0% | 价格已在模型认为的乐观价值之下 → 风险收益比无穷大、风险约束永不触发 | 悲观损失加 5% 下限（任何期限"零亏损"都不成立） |
| 自身估值分给得太满 | 分位 0 给 95 分，读起来像"几乎满分" | 收到 88/10 区间 —— 历史分位只说明"在自身历史里的位置"，不含"值多少钱" |

### 4.2 界面验收时暴露并修掉的 2 个问题

第一版在界面上看过之后又发现两个，都是**结构性**的（不是显示问题）：

| 问题 | 现象 | 根因 | 修法 |

修后：行业 340301 成分 18，加权 PE 19.7 / 中位 PE 24.7，对中位 -20.2%，行业内 PE 分位 32%

`0` 在界面上还会显示成「—」而不是 `0%`（见 §2.4 的缺值规则）：`0.0%` 会被读成
"与行业持平"，而它的真实含义是"算不出来"。

### 4.3 行业体系混存 → 已解决（吃下 82 个申万快照）

`industry_members` 是**两套体系混存**：

| 体系 | 来源 | 覆盖 | `industry_name` |
|---|---|---|---|
| `eastmoney` | 日更快照 | 2026-10-08 起，每交易日一份（5 个快照） | 中文名（如"白酒Ⅲ"） |
| `sw` | 申万 `StockClassifyUse_stock.xls` 回填 | **2020-01-23 起，82 个快照** | **就是代码本身**（如 "340501"） |

原来取"代码最长的那条"（= 最细一级），带来两个后果：同一只标的**在不同日期
落在不同体系的代码里**（行业时间序列断裂），而且申万那部分没有中文名。

已按下面的方案实现：

| 层 | 新增内容 |
|---|---|
| `cnlake/industryasof.go` | `IndustryMembersAsOf(asOf, system)`（按日期取快照 + **前向填充**）、`IndustrySystems()`、`PickIndustrySystem()`、`IndustryMembersByDateRange()`。**`IndustryMembers()` 语义一字未改**（`provider.go` / `scope.go` 仍在用），由 `TestIndustryMembersUntouched` 钉住 |
| `service` | 选定单一体系（`PickIndustrySystem` → 实测选中 `sw`）；行业码统一带体系前缀 `sw:340501`；体系名写进 `Snapshot.DataCutoff`；`industryDisplayName` 把"名称即代码"的申万那一路显示成「申万 340501」 |
| `service/valuation_industry_history.go` | **按快照日重建行业历史加权 PE 序列**（时点正确：该日生效的成分 + 该日生效的股本 + 该日已披露的 TTM） |
| `valuation` | `SampleValuationAt`（按给定日期采样）、`WeightedPEAt`（调和加权，亏损公司退出分母） |

**效果**（`TestIndustryBenchmarkUsesFullMarket` 断言）：

```
行业历史分位：226/336 个行业有真实分位，250 个有历史区间
历史序列起点 2021-01-29，69 个行业快照日全部算出值
```

这带来两个此前做不到的能力：

1. **行业环境分回到"历史分位"口径** —— 之前只能靠"加权与中位 PE 的背离"
   这个横截面口径，回答不了"行业比它自己历史上贵还是便宜"。
2. **历史行业归属不再有前视偏差** —— 每个时点用该时点生效的成分名单。

#### 4.3.1 性能：一次踩坑与修法（值得记下来）

行业历史序列第一版用 `valuation.BuildValuationSeries`（逐**交易日**建 1400 个点）
来取样，但实际只需要**行业快照日**（69 个）上的值。实测：

```
行业历史序列重建   159497 ms   ← 全市场 5384 只 × 1400 天 ≈ 750 万次点构造
整次评估           3m4.6s
```

改成"只对快照日直接算市值与盈利"（两次二分查找 + 阶梯函数二分）之后：

```
行业历史序列重建     2510 ms
整次评估            27.6s     ← 与加功能前的 25~30 秒同一量级
```

#### 4.3.2 仍未解决的一点（已如实标注，不假装）

**行业阶段判定需要成分股的营收增速**，而那只有被评估到的标的才有。
评估范围取「前 N 只」（默认前 150）时，多数行业只有少数成分带基本面分，
于是 `Stage` 仍是 `unknown`。每个行业的说明里会写出实话，例如：

> 本行业 132 个成分里只有 0 个（0%）在本轮评估范围内跑过基本面评分
> （本轮共评估 150 只，按市值取前 N）—— 行业阶段与基本面分位仅对这 0 个有效；
> 把评估范围调到「全市场」可消除这一限制

界面上有「全市场」按钮，这一点是可操作的，不是死路。要彻底消除需要给
全部 5000+ 只标的都跑评分（约 +60 秒），目前按需触发。

**验收 9 / 10 的状态更新**：行业历史分位与历史行业归属已经可用了，
所以这两条从"部分满足"升到**除指数成分外基本满足**；
仍受限的是 `index_constituents`（只有 1 个快照，且 CSI 系列无免费历史源）。

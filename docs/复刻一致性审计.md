# Go 复刻 vs Python 原实现 —— 一致性审计汇总

审计方式：三个子代理分别精读两边源码做交叉比对（评分公式 / 轮动决策 / 数据模型与编排）。
**Python 为权威**。只记录真实不一致，风格差异不计。

---

## 一、核对确认**一致**的部分

不是凑数，是逐表达式核对过的：

- **五个基础分**每一项系数与阈值（trend 8/8/6/4/2/2、structure 8/4/1 + 6/3 + 4 + winRate、rs 14/6 与过热冷却 -1/-2、capital 7/4/2/2、near_repair 6/4/2/1.5/1.5）
- **四个策略**的每一项加减分、上下限、折算比例（`/36*30`、`/50*20`、`mainline_proxy` 三分支 max、全部惩罚项）；分项上限无混用
- **总分合成**：`clip(五项直接相加 + 调整分, 0, 100)`，不是加权平均
- **修复能力**：事件条件、40 日窗口、10 日间隔、**41 日延迟入账**、累计语义、ability 公式
- **所有 rolling 的 min_periods**（含 `prev_high60 = shift(1)+rolling(60,20)`）
- **横截面分位**（并列平均名次 = `rank(average, pct=True)`）、相对强度基准 `000300.SH`、行业收益均值
- **9 个优先级分支的顺序与条件骨架**（含优先级 7 内层 4 子分支）
- **各判定函数**：结构破坏 7 条、超跌失败 4 条、可修复回踩、急涨兑现、等反弹、大反弹阳线、弱势单层
- **candidate_quality_ok** 的全部分数线与追加条件、`replacement_mode` +1
- **换股配对**：分差门槛 `max(20, replace_score_gap)`、force_clear 免分差、低吸永不换股、全局上限 `max(1,min(3,target//2))`
- **hold_compare** 三个 gap、`expected_portfolio_uplift`、`rank_no` 规则、非配对行 `expected_improvement` 恒 0
- **执行语义三元组**（manual/semi_auto/auto）
- **apply_rotation**：clamp 3、整表重写、加层分母 `target_layers`、建仓日期规则、`created_at` 沿用、手动组合拒绝
- **市场状态**：代理指数累乘、20 日 vs 前 20 日高低点结构、bull/bear 公式、`≥75 且领先 +10`、三种标签、80 日窗口、<20 天判 range（**除 amount_growth，见 M13**）
- **策略配置表**全部参数；低吸的 sort_mode/position_mode/利润保护/clear_ready_count/daily_max_new_adds（**除 exit_ma30_ratio，见 M5**）
- **SQLite 表结构**与 DuckDB 一一对应，无丢字段；action 枚举完整

## 三、中等

### 数据丢失级（优先）

- **M9 `UpdatePortfolio` 没有"省略即保留原值"语义** —— Python `base = dict(current or {})` 逐字段回退；Go 直接整体覆盖。**局部更新会把 `strategy_id` 打回趋势成长、`benchmark_code` 打回 000300.SH、`status` 打回 active、`scope_value_json` 清空、`notes` 清空**。前端整表单提交时无感，API/脚本调用会静默丢数据。
- **M11 新增持仓无代码合法性校验 + 允许 0 成本** —— 可写入 `AAPL`、`1234`；0 成本时 `profit_loss_pct` 恒 0、`highest_price` 退化成现价 → **浮盈保护永不触发**，界面无报错。

### 评分侧

- **评分-4 基础分多加了 `>0` 保护**（Python 先 `fillna(0)` 后不设保护）→ 次新股（上市 30~249 日）总分**低 10~20 分**
- **M5 低吸 `exit_ma30_ratio`**：gem/star/gem_star 写成 0.96，应为 0.94 → 止损线提前
- **M10 expert 主线门槛退化**：`industryEdge` 硬编码 0，只看恒 0 的 `MainlineScore`
- **评分-2 `industry_strength_pct` 在行业层排名**，Python 在**个股层**（影响 capital +2、主线修正 ≤6、高手 mainline_proxy ≤21）
- **M13 市场状态 `amount_growth`**：Go 用求和 + 基期取 -10..-5 日；Python 用均值 + 基期 -25..-21 日 → ±10 分项，可能翻转 bull/range
- **评分-5 / M11 低吸候选**：漏 `ma250 > ma250_prev`、`ma5 > ma5_prev`；**`ret20` 误用相对强度**（根因：`score.Row` 无 `StockReturn20D`/`Ma5Prev` 字段）
- **评分-6 低吸 drawdown 永远用宽档**（实参写死 0，已随 S1 部分修复）
- **M8 `MaxDrawdownPct` 恒 0** —— 注释说"阶段一无数据来源"已过期，`stock_strength` 已存 `drawdown_from_high_120`
- **M15 组合评分 / 健康标签整体缺失**（`portfolio_score`、`health_label` 强势/稳健/观察/风险）

### 轮动侧

- **M1 候选池 `head(80)` 与质量过滤顺序反了**，且缺 `prioritize_trend_growth_entry_points` 加权排序 → 候选集合与顺序都不同
- **M4 配对前缺 `quick_profit_take` 预筛** → 产生"有换入、无对应换出"的悬空行
- **M6/M7 `pair_mode` 判定位置与计数递增位置不对**
- **M2 配对遍历次级排序键不同**（缺 rs20/repair/layers）
- **M3 配对候选行动作**：partial_rotate 在 Python 是 `add`，Go 一律 `replace_in`
- **M5' `force_clear` 未含 `oversold_failed`**

### 编排/数据侧

- **M7' 行业/概念范围过滤语义不同** —— Go 统一用 `strength.Industry`（板块优先级第一名，可能是概念板块）；Python 行业用 `board_type=='industry'` 成员并集、概念只用 `concept` 成员 → **概念范围几乎永远匹配不到**
- **M8' 持仓不套用组合范围** —— Python 持仓也走 `_scope_filter`，范围外持仓评分/现价记 0；Go 不带范围条件
- **M12 缺评分行的持仓**：`HighestPrice`/`HoldingTradeDays` 被记 0（Python 与是否有评分行无关）→ 浮盈保护与持有交易日类规则失效
- **M17 `entry_date` 缺省回退到"今天"**而非最新交易日
- **M10' `strategy_id` 别名回退链缺失** —— 传 `low_buy`/`超跌反弹`/`mainline` 会静默变成趋势成长
- **M12' `max_stock_count` 没做 `max(target, ...)` 抬高**
- **M18 apply：keep/observe 也写流水**；加层流水的 `price` 是加权成本而非收盘价
- **M14 apply：新建仓 `last_action`/`source_type` 不对**（Go "apply_rotation"/"manual" vs Python "add"/"system"）

## 四、单列评估：现价来源差异

| | Python | Go 详情页 | Go 建议页 |
|---|---|---|---|
| 现价 | 最新**评分日** `close_price` | 最新**交易日**收盘价 | 评分日收盘价 |

**关键问题：同一程序内两个页面会打架。** 当评分日 < 最新交易日时（当天还没刷新评分），详情页显示今日现价/浮盈，建议页与清仓判定用的是评分日旧价 —— **用户看到 +8%，系统按 +3% 判定**。Python 两处同源，永远自洽。

日常场景（评分已刷到最新日）数值完全相同，所以只在"评分为旧 / 股票不在评分表"时暴露 —— 恰好是用户最容易察觉"界面与建议对不上"的两处。

**建议**：详情页标注"现价=最新交易日收盘、建议基于评分日 YYYYMMDD"，或统一成同一来源。

# 组合回测一致性核对结论（Go vs 原版 Python）

> 核对时间：2026-10-12
> 触发问题：「freeStock 的回测结果不如原版，策略生成逻辑 / 买入卖出逻辑是否一致？」
> 原版权威路径：`D:\workspace\python\stock\tushare-stock-tonyz\pythonProject\pythonProject`
> 本次核对**以实跑对账为主**（不是读代码猜），辅以两路只读代码审计。

## 一、结论（先看这一段）

1. **「策略生成逻辑 + 买入卖出逻辑」是一致的。**
   取同一个组合（主板+创业板、趋势低吸、target=5/max=5/10 层）、同一段区间、同一份数据，
   两边跑出来的成交与净值**逐笔、逐日完全相同**（详见 §二）。
2. **回测结果差异的根因在「数据覆盖」，不在策略/买卖逻辑**。三条，按影响排序：
   - **R1（最主要）**：`stock_strength` 里 **2023-10-09 ~ 2024-10-17 的评分行，长周期均线是 0**（同一天里约 5,100 只票的 K 线窗口被截断到 2023-10-09）。低吸候选条件要求 `ma120/ma250/ma250_prev > 0`，于是**这 1 年多里根本产不出低吸候选** → 无法建仓。
   - **R2**：`stock_strength` 只回溯到 **2023-10-09**（原版评分表回溯到 2021-08）。跑 4 年区间时，前面 **240 个交易日完全没有计划**（整天空仓）。
   - **R3**：数据湖指数日线只有 **2023-10-09 起**（`curated/index_bars`），指数闸门要的 MA250 到 **2024-10-18** 才算得出来 → 2024-10-08~17 那 8 天闸门被误关（原版是开的），2024-10-21 那笔建仓因此没发生。
3. **指标公式（总收益/年化/夏普/回撤）两边一致**；界面上看到的年化差异来自**区间天数不同**（`(1+r)^(252/天数)-1`，天数取自各自实际跑的交易日数），不是公式不同。
4. 另外发现 5 处**会影响实盘建议**（对趋势成长/超跌/高手模拟影响明显，对低吸几乎中性）的差异，见 §四。

## 三、根因明细

### R1（最主要）评分行的 K 线窗口被截断 → 长周期均线恒为 0

**观测事实**（`stock_strength`，2026-10-12 的「全量重算区间」结果）：

| 评分日 | 各票「最深非零均线」分布 |
|---|---|
| 2023-11-20 | `ma20: 5136`、ma60: 1、ma120: 43、ma250: 102 |
| 2023-12-29 | ma30: 79、`ma60: 5103`、ma120: 38、ma250: 101 |
| 2024-03-15 | ma30: 28、`ma60: 5198`、ma120: 31、ma250: 101 |
| 2024-05-07 | ma30: 13、ma60: 83、`ma120: 5173`、ma250: 96 |
| 2024-09-25 | ma30: 8、ma60: 15、`ma120: 5262`、ma250: 68 |
| **2024-10-18** | ma30: 13、ma60: 12、ma120: 336、**ma250: 4999** |
| 2025-01-03 | ma30: 13、ma60: 32、ma94: 94、**ma250: 5244** |

也就是说：在 **2024-10-18 之前**，绝大多数股票在评分时只拿到了
「从 2023-10-09 到评分日」这一段 K 线（2023-11-20 是 30 根、2023-12-29 是 60 根、2024-05 起是 120 根），
**窗口的起点被钳到了 2023-10-09**，而不是应有的「评分日往前 320 个交易日」。

**为什么这会让回测变差**：
- `isLowBuyCandidate`（`internal/score/candidate.go:538-566`）第一行就是 0 值前置校验：
  要求 `ma120 > 0 且 ma250 > 0 且 ma250_prev > 0 且 ma5_prev > 0`；
  长周期均线为 0 → **整个 2023-10-09 ~ 2024-10-17 产不出任何低吸候选**（只有每天约 100 只「恰好在表里已有完整历史」的票例外）。
- 同一时段低吸广度就绪数（`close>MA60 且 MA20>MA60` 的只数）：
  - 2023-10-09 ~ 2023-11-16：Go **14~39** vs 原版 **543~2005**
  - 2023-11-17 ~ 2023-12-28：Go **42~52** vs 原版 **1969~2820**
  - 2023-12-29 起才对齐（Go 1491 vs 原版 1500）
  就绪数 <1000 → `_low_buy_dynamic_target_count` 返回 0 → **不开新仓**；这就是 Go 在 2024-05-07 才有第一笔成交的原因。
- 2024-03-14/15、2024-09-24/25 那几天两边的**闸门与广度都一致（都允许建仓）**，但 Go 因为候选条件要求 `ma250>0`（当时仍为 0）而选不出票 → 错过 601156 与 603663 两笔满仓大仓。

**机制（待确认）**：长周期均线为 0 的是**同一批约 5,100 只票**，另有约 100 只票始终有完整均线
（它们走的是 `lakeProvider.barsFor` 里那条**逐只回落到 `lake.DailyBars(code, 年, 年)`** 的慢路径）。
批量缓存那条路（`internal/service/provider.go:707-1086`：`cachedBars` / `fillBulk` / `TrimBulk`）
理论上会向左补齐窗口并合并，但实测结果与「`bulkFrom` 被推进到 2023-10-09 却没真正读到更早的行」一致
—— 代码里已经为此留了两条诊断日志：

```
⚠ 数据湖批量读：该段没有日分区，却推进了覆盖区间（后续会被判成「无数据」）
⚠ 数据湖批量读读到 0 行，却推进了覆盖区间（后续会被判成「无数据」）
```

**建议下一步（需在 Go 侧实跑，本机沙箱不能跑 go test）**：
1. 在 `loadScoreInputs`（`internal/service/scoring.go`）里对某一天打印
   `len(bars)` 与 `bars[0].Date`（例如 2023-11-20 取 000001.SZ，正确值应是 ~319 根、首根 2022-07-28）；
2. 打开 `数据湖批量读开始/完成` 日志，核对 `bulkFrom` 是否早于请求的 `start`；
3. 若能复现，修 `cachedBars` 的覆盖判定 / `fillBulk` 的 `bulkFrom` 推进逻辑（或让 `cachedBars` 在
   「该票切片起点晚于 start」时返回 miss，强制补读左边）。

**修复前的影响面**：不只是低吸回测 —— **这 1 年多里所有策略的评分都是残的**
（趋势成长的 MA250 项、`drawdown_from_high_120`、`range_position_120` 等都受影响）。

### R2 评分/日历起点差 240 个交易日

- freeStock `stock_strength`：3,784,847 行 / **728 天 / 2023-10-09 起**（且 2023-10-09~11-16 每天只有 146 行）。
- 原版 `stock_strength_history`：10,245,353 行 / **1221 天 / 2021-08-02 起**，低吸每天 ~4,895 行。
- 引擎的交易日集合来自价格日；价格日来自 `loadBacktestBars(codes, …)`，而 `codes` 又来自评分表 →
  **评分表没有的交易日，那天 `pending_plan` 恒空 → 整天空仓**。
- 实测：请求 2022-10-12~2026-10-12 时，`tradingDates` 有 968 个交易日，评分只覆盖 728 天 →
  前 240 天没有任何交易。`CreateBacktest` 已经会在这时打一条覆盖率警告（`backtest.go:142-150`），
  界面上也会带 `scope_warning`，但结果本身仍然是「跑完了、收益偏低」。

> 数据本身是够的：数据湖 `daily_bars` 有 2016 起的分区（2023 年起才全市场覆盖）。
> 所以要跑 4 年回测，需要 **对完整区间重跑一次历史回填**；但受 R1 影响，重跑出来的早期评分仍然是残的。

### R3 指数日线只有 2023-10-09 起 → 指数闸门暖机不足

- 数据湖 `curated/index_bars` 只有 2023~2026 四个年分区、8 个指数、共 5,824 行，最早 2023-10-09。
- 闸门需要 创业板指 `close/MA20/MA60` + 长周期健康（创业板指与沪深300 的 `MA250`）。
  MA250 要到 **2024-10-18** 才能算出来；在那之前只要广度 ≥2400 就会被判「弱周期假热度」而**关闸**。
- 逐日复算 2023-10-09~2026-10-09：`entry_allowed` 有 **9 天不同，全部是 Go=关、原版=开**
  （2023-11-15；2024-10-08~10-17）。
- 修复方向：把 `index_bars` 回补到至少「回测起点前 250 个交易日」（原版是 2021-08 起）。
  这属于**数据补齐**，不是改逻辑（改逻辑会和原版不一致）。

### R4 市场状态：freeStock 用 400 只抽样，原版用全市场帧

- `internal/service/scoring.go:577-686`：从全市场等距抽 **400 只**，聚合成交/涨跌家数算市场状态；
- 原版 `portfolio_service.py:1790-1814` + `volume_price_market_state.py`：用**全市场 ~5,000 只**（且是 A 股前缀白名单内的）。
- 逐日对比：本次实测 **2025-10-13 ~ 2026-09-18 的 232 个交易日里有 54 天不同（23%）**；
  另一路审计在 2024-10 之后的 694 个共同交易日上测得 **9.8% 不同（2024-12 之后 12.3%）**。
  主要方向 Go=bull/Py=range 22 天、Go=range/Py=bear 19 天。
- **对低吸策略中性**（低吸的 `desiredCount`、`canAddNewPosition`、退出判定都不读市场状态 —— 这也解释了为什么低吸的 1 年窗口能逐笔一致）；
- **对趋势成长 / 超跌 / 高手模拟影响实质**：熊市要减半目标只数与层数、且 `allow_new_adds=False`。
- 顺带：抽样池含北交所（920）与 302 段，原版的白名单里没有这些票（`internal/portfolio/ashare.go` 是白名单，但抽样走的是 `GetStockUniverse`，没套白名单）。

### R5 信号表是空的（原版 4108 条）

- freeStock `signal_history`：**0 行**；原版 `research.duckdb.signal_history`：4,108 行（2021-10 ~ 2026-09，全是 buy）。
- 低吸几乎不受影响（`isLowBuyCandidate` 不读信号、低吸加层/overflow 都短路），
  但**非低吸**受影响：熊市候选闸门会把每只票都判成「无新鲜信号」而拒、`signal_bonus` 的 2 分缓冲、
  `initial_entry_layers` 的 bull/range_ready 两条（首次建仓 2 层）、overflow 门槛、加层信号分支。

### R6 换股配对漏了一条门槛（Go 更激进）

- 原版 `portfolio_rotation_logic.py:2225-2227`：非 `force_clear` 分支**也要** `cand_score >= policy.ready_score`。
- Go `internal/score/candidate.go:107-116`：只在 `forceClear` 分支校验 `TotalScore < cfg.ReadyScore`，
  普通换股/`rebound_ready` 分支只比分差。
- 后果：候选带新鲜信号时质量门槛会降到 `max(ready,base)-2(+1)`，对 `expert_simulation`（61<62 / 63<64）
  与 `oversold_rebound`（69<70，floor=0 的票）**真实可达** → Go 会产出原版永不产出的换股行（并挤掉一条 add）。

### R7 候选排序的 `signal_priority` 没看信号年龄

- 原版 `:1717-1722`：`fresh_buy/fresh_candidate` 都带 `age <= limit`，**过期信号记 2**（最差）。
- Go `internal/score/candidate.go:631-669`：只按 `SignalType` 给 0/1/2，不看 `SignalAge`。
- 后果：总分并列（总分 round(2)，同分常见）时，陈旧 buy 行在 Go 里排到新鲜 candidate_buy 前面 →
  影响 `head(max(80,target*12))` 边界取舍与配对选中哪只。

### R8 北交所/302 混进候选池与分位基数

- `markets=[]`（全市场）时 Go 的 `inScopeFieldsParsed` / `MarketInScope` 一律放行 → 920（每天约 293 行）进池；
  302 段（market=chinext）在任何含 gem 的范围里也放行。原版的行情帧正则（`portfolio_service.py:1256-1258`）把它们彻底删掉。
- 横截面分位（`amount_rank_pct`/`turn_rank_pct`/`industry_strength_pct`）Go 在含 920/302 的全集上排名，
  原版在白名单帧上排名 → 每只票分位偏移 ≤5%、`capital_score`/`total_score` 差 0.05~0.4（实测）。

## 四、已核对一致（不必再查）

- **引擎时序**：信号 T 日收盘生成、**T+1 开盘执行**，执行价 `open`、盯市 `close`；当日无评分则 `pending_plan=None`。
- **执行语义**：先清仓/换出 → 再减仓 → 后买入；买入按 `rank_no`、评分降序、代码升序；层预算 = 总资产/`total_layers`；
  买入成本价含手续费；`max(amount*rate, min_commission)`；印花税仅卖出；滑点买加卖减、`pct`/`fixed` 两种、round(2)。
- **指标公式**：总收益 = 末个累计收益；年化 `(1+r)^(252/天数)-1`；波动率用样本标准差(ddof=1)×√252；
  夏普用 **round 后的年化**；卡玛/索提诺/Alpha/Beta/信息比率、胜率（分母是全部卖出）、平均持有天数（1 位小数）逐条一致。
- **策略配置表**：四个策略的每一项加减分、上下限、折算比例，9 个优先级分支，广度阈值表（70/20/62/5/60/2、universe<100 不启用）、
  低吸四档（1000/1500/2000/2600 与 conservative1200）、900 清仓线、2400 热广度、7 档低吸 profile（含 `exit_ma30_ratio` 只有 main_gem=0.96）、
  `initial_entry_layers`、`can_add_second_layer`、`overflow`（限额 7/7/0 等）、`max_replace_count`、`candidate_quality_ok` 全部条件 —— 逐条核对一致。
- **score 分项**：同一交易日 `trend_score` / `structure_score` / `rs_score` 两边 **100% 相同**；
  `capital_score` 均值差 0.05~0.15、`repair_score` 差 0.2~0.5（后者是修复能力的累计窗口长度差异）。
- **范围过滤集合 = 广度统计帧**；`readyByDate`（低吸广度就绪数）口径与白名单一致（2025 年后中位差 +8）。

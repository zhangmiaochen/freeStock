## 2. 实现口径（与 `开发说明_v3.md` 一致）

- 股票池：沪深 A 股（主板+创业板+科创板），不含北交所；
- PIT 财报：`announce_date <= 调仓日`，先取最新 `report_period`，同周期取最新公告；
- 过滤：上市≥250 日、20 日均额≥3000 万、ROE(年化)≥8、营收/净利同比≥0、毛利≥15%、负债≤70%、现金流/净利≥0.3、收盘>MA200、20 日回撤 ∈ [−20%, −2%]；
- 打分：质量/成长/安全 0.4/0.4/0.2，截面百分位（**并列取平均名次**）；
- 权重：`raw = 0.05 + r²` 归一化，单票上限 15% 迭代配平；
- 仓位：沪深300 < MA200 时 ×0.5；
- 调仓：每月最后一个交易日，次日开盘成交；
- 免打扰带：权重换算成 100 层（1 层=1%），层数不变不下单；
- 成本：佣金 0.03%（最低 5 元）+ 印花税 0.1%（卖）+ 滑点 0.1%。

## 3. 本轮审计发现并修掉的两个问题

### 3.1 并列名次处理不一致 → 回测结果不可复现（已修）

- 现象：同一区间连跑两次，总收益会出现 5~10pp 的差异（例如 2019-2026 出现 203% / 213%）。
- 根因：`rankPct` 用"稳定排序后依次给不同名次"，并列值（大量股票营收/净利同比恰好为 0）拿到不同分数；
  而候选顺序来自 map 遍历，**每次运行都不同**，于是分数、排名、持仓都会漂移。
- 修复：并列值取**平均名次**（与 pandas `rank(pct=True)` 一致），同时把 `priceBars` 按 (date, code) 排序。
- 验证：同区间连跑两次结果完全一致；全区间候选分数 checksum 两次相同（`36993.402593`）。

### 3.2 与 Python 参考的年度差异：复权口径不同（不是算法错）

- 现象：Go 与 Python 的 6 年总收益接近（121.4% vs 120.9%），但 2023、2024 年差 5~6pp。
- 定位：以 688091（上海谊众）为例，2023-06-30：
  - Python 缓存收盘 55.92、MA200 59.76 → **收盘在 MA200 下方，被过滤**；
  - Go 数据源收盘 110.49、MA200 109.66 → **在 MA200 上方，入选**。
- 原因：688091 在 2023-04-25 有 **10送1**（理论跌幅约 −9%）。
  Python 的拆股识别阈值是"单日跌幅 < −22%"，**漏掉了这次送转**，把 9% 的送转当成真实下跌；
  Go 用数据源的完整复权序列（含送转与分红），没有假跌幅。
- 同类事件：2023-2026 的送转里约 10.6% 理论跌幅落在 −11%~−22%，Python 全部漏判。
- **结论：Go 实现是正确口径，Python 参考在事件附近有偏**；本文件第 7 节起以 Go 为准。
